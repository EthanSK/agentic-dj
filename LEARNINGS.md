# Project learnings

- The next-round control downloads a private brief; it does not contact an agent. Both handoff surfaces must describe that download and permit the user to request any count. The exported brief defaults to ten only when the accompanying request gives no count.

- Browser listening preferences persist separately from private library state. Restore volume (including zero) and preview permission after mount; save only on explicit preference changes so initial defaults never overwrite stored values. Reload must not automatically resume playback. Storage failures must leave live controls usable.

## Durable implementation facts

- Bandcamp public release pages expose structured `data-tralbum` metadata with track IDs and preview availability. Read the structure, not stream URLs; a track ID is sufficient for the official embed.
- Direct Bandcamp track pages and album pages have different price scope. Only direct-track metadata can justify `scope: track`; release-level minimums must stay labelled as release pricing.
- Some Bandcamp artist URLs redirect to custom domains. The metadata helper deliberately rejects custom domains instead of turning a music helper into an arbitrary URL fetcher; verify those sources separately.
- Not every track listed on an album exposes an embeddable preview. Curated demo crates must verify `hasPreview` for every selected track.
- The local database seed uses `INSERT OR IGNORE`. Updating bundled crate JSON must never overwrite existing votes; ship a deliberate, identity-safe crate import or migration when existing installations need new content.
- Vote writes use a read revision plus a compare-and-swap update. Idempotency IDs handle retries; revision checks handle concurrent tabs. Neither mechanism replaces the other.
- Undo must compare the current vote with the history event’s `after` value. Replaying an older undo over a newer decision is a data-loss bug.
- Imported recording IDs may refresh metadata only when normalised artist and title still match. This prevents an old vote from attaching to a different recording.
- Spreadsheet exports need formula neutralisation for values beginning with `=`, `+`, `-`, or `@`, including after leading whitespace.
- Local update safety needs three distinct recoveries: refuse a dirty source tree, back up ignored private state while the server is stopped, and retain the old Git commit on a recovery branch. Do not silently reset or roll back.
- New discoveries append to the end by default: preserve remaining tracks and their order. Explicit round replacement preserves tracks, votes and profile data and sets an unfinished round aside. Keep the inferred Earprint provisional and raw decisions, tags and notes as the primary evidence for future curation.
- `later` is a completed listening decision but a neutral taste signal. Count it toward round progress without treating uncertainty as either a positive or negative preference.
- The tenth decision must open the completed-round handoff regardless of the current queue filter. A browser-only build must download an explicit private agent brief rather than imply it contacted an AI service by itself.
- Independent taste models are useful for identifying missing experimental axes, but their discography recall is not source evidence. Verify every named recording against an official page and the owned-library reference before it enters a round.
- Bandcamp's official cross-origin embed accepts only a load-time `volume` query and exposes no parent-page runtime volume control. Use a `GainNode` in the local Web Audio player for live volume without resetting the playhead.
- Existing installations can receive richer bundled DJ metadata without rewriting their database on startup: overlay only missing fields for the same stable ID plus normalised artist/title, never replace local metadata, votes, history, or profile state, and let the next ordinary mutation persist the enriched payload.
- A cross-origin preview can become Chrome's active Media Session even when the parent page only embeds it. A top-frame no-op handler does not override a child frame's session, and current Chromium does not implement the Media Session permissions-policy token. Do not use an `<iframe>` or `<audio>` element in the listening path when hardware-key isolation is required.
- Chromium registers Web Audio playback as an ambient player rather than a controllable media session. Fetch the official Bandcamp preview through the strict local relay, decode it into an `AudioBuffer`, and use `AudioBufferSourceNode` plus `GainNode` for play, pause, seek, and volume.
- React development remounts and hot replacement can run Web Audio cleanup more than once. Clear the stored context before closing it, check for the `closed` state, and handle the close promise so cleanup stays idempotent and never creates an unhandled rejection.
- Media-key acceptance requires real routing evidence. A registered JavaScript handler, DOM marker, or ordinary unit test does not prove what an actual macOS hardware key controls.
- The listening desk's primary job is one record followed by Keep, Pass, or Later. Keep preview level and DJ facts visible, but put taste explanations, feedback, filters, shopping provenance, and agent-loop tooling behind labelled progressive disclosure; audit every old control and export before removing visible copy.
- The health endpoint is part of installed-version verification. Read its version from `package.json` at build time instead of maintaining a second hard-coded release number.
- Spotify playlist pages virtualise long track lists. A visible first batch is not a playlist inventory: verify the reported total, collect every numbered row across the virtualised range, and prove there are no missing positions before calling the reference complete.
- Treat Rekordbox playlist hierarchy as graded evidence, not one flat list of favourites. A deliberately curated best list can be a strong positive signal, while good, okay, meme, overlay, and own-track lists retain their narrower set-building meaning; current Keep and Pass decisions still outrank older library placement.
- A store does not change an exact recording's tempo. For purchase curation, compare version, duration, ISRC, phrasing, and grid stability before source price: Qobuz may carry the correct full lossless recording, while Beatport may expose a genuinely different extended/DJ mix.
- Treat half/double-tempo store metadata as orientation evidence, not a rejection rule. Values such as 70/140, 79/158, 82/164, and 86/172 need an audio/grid check, and even a DJ store can publish a musically questionable BPM analysis.
- A recent-likes purchase window needs two independently verified boundaries: a complete Spotify position/date capture and a defensible Rekordbox import-date event. Label the latter as a proxy for buying unless purchase receipts prove the date directly.
- A fixed-budget purchase manifest may use an authenticated price snapshot to prepare an exact-cent draft, but the live cart must recheck price, availability, already-purchased status, format, and final subtotal before payment. Keep the draft, financial confirmation, download, and Rekordbox write as separately verified stages.
- Keep personal-source crate browsers under the ignored `work/` tree and serve them on loopback only. Qobuz album pages expose the exact release artwork in `og:image`; before handing off a visual crate, prove unique release/art URLs, image responses, row count, and snapshot total without publishing the user's listening history.
- Bandcamp may return a metadata-free response to a server relay that uses runtime-default request headers while returning the full embedded player to a normal browser request. Send a bounded browser-like `Accept`, `Accept-Language`, and `User-Agent`, then still validate the returned track ID and strict `bcbits.com` stream path before relaying audio.

- Ethan's Agentic DJ preference: "Don't use Spotify anymore" for listening, embeds and preview fallbacks. His liked songs can still supply discovery identities. Missing previews must stay explicitly pending, not imply purchase unavailability or become negative taste evidence automatically.
- Beatport public track pages expose a CORS-enabled `geo-samples.beatport.com/track/<UUID>.LOFI.mp3` preview when their own player loads it. Record the observed sample UUID against the verified recording; fetch that public sample directly through the existing Web Audio engine, without adding an audio proxy or controllable media element. Numeric catalogue IDs are not sample UUIDs.
- Beatport's own catalogue search can locate exact versions omitted by web-search results. Compare artist, mix, album and length: identical titles can identify different recordings (including Kraftwerk's Computer World and The Mix versions). A search non-result is not proof of unavailability.
- The existing undo command can reopen a specific older decision by event ID while preserving later decisions and the complete history. Its current-vote equality guard must pass; never clear all Passes to recover unavailable-preview skips.
- Before importing a new listening round, compare normalised artist and title against both saved Agentic DJ tracks and the current Rekordbox database. Report zero exact matches as a bounded duplicate check, not proof that no copy exists outside Rekordbox or under different metadata.
- Round navigation and shortlist exports are different scopes: the active crate controls progress, while Keep history must be derived from all saved votes and retained tracks. Own the Web Audio engine above the changing track card, deduplicate and bound decoded preloads, and preload the next playable track so filtering or browsing cannot interrupt the current preview.
- Preview continuity keeps audio alive while the listener explores filters or saved tracks. After a successful Keep, Pass, or Later, reset the preview and carry forward active playback to the next supported track; paused previews stay paused and completed rounds stop. Invalidate pending playback on stop so a delayed load cannot restart a discarded track. Show the crate description beside round progress so a short lane label is not the only musical context.
- GitHub Pages is a static public explanation of Agentic DJ, not a hosted copy of the listening desk. Keep the stateful app loopback-only and never publish personal tracks, votes, playlists, profiles, or agent briefs with the site.
- Explicit queue-row selection must use idempotent play of that recording, not a global playback toggle. Toggle pauses only when the requested recording is already playing; switching recordings stops the previous source and invalidates delayed requests. Tab browsing alone must keep the existing audio alive. Round-completion handoff must be a transition from incomplete to complete, not a reaction to editing an older Keep after a round has finished.
- Loading an external new crate resets the browsing scope and filters while retaining a loaded recording that still exists. Ordinary same-crate reloads preserve browsing state; a full page reload restores the saved tab-local recording without autoplay.
- The active crate alone is not historical provenance. Retain per-track `rounds` memberships through initialisation, reimports, CSV, JSON and agent briefs. Recover old memberships only from identity-matching saved crates; retain unnumbered crate names without inventing round numbers. Historical recovery must not replace track metadata, votes, profile, history or active crate.
- Listening sessions scope shopping counts and exports, while global votes remain the taste source. Infer legacy sessions from decision dates; never treat metadata refreshes, reads or agent imports as listening activity. Manual sessions and the greater-than-14-day rollover preserve the active queue and all earlier decisions.
- Keep unavailable previews out of listening lists rather than generating Pass votes. The private Beatport-only preference requires an exact track page plus typed official preview for new discoveries; preserve unresolved and older owned records in history. Beatport cover images use the separate `geo-media.beatport.com` allowlisted host.
- Exclude private work snapshots from TypeScript's broad source glob. Git ignore rules alone do not stop old copied source from breaking type checks.
- Keep discovery provenance separate from playback and shopping sources. Ethan wants to see if each suggestion came from Spotify likes, past Keep decisions, Rekordbox or his own request. Save this on the track, preserve it on metadata refresh, and carry it through every session, export and agent brief. Recover legacy values only from verified source records; a Spotify-shaped ID or Beatport preview is not discovery evidence.
- The session header needs a second row before its logo, summary and actions collide, including at browser zoom sizes. Keep each session fact unbroken and let the summary wrap between facts; checking only page overflow can miss overlapping grid children.
- Keep-order ranks are separate from the append-only audition queue. Sort and export only the chosen Keep scope, and use saved Keep dates for Date added. Duration totals sum full recording metadata and flag missing values.
- Do not edit a live listening server with hot reload enabled. The default runtime disables source watching and HMR; use AGENTIC_DJ_HOT_RELOAD=1 only on an isolated test instance. Preserve the selected recording and actual recent preview starts in tab storage so a manual reload does not lose the user's place. Reload is still not autoplay permission.
- List tabs, list filters, sort and session browsing must not change the loaded record or its player. Non-audition lists select a separate row, then use an explicit Load into player action; the primary card, sound and navigation remain one context. Arrow keys navigate that context, while P/K/L make decisions. Preview sample IDs and catalogue recording IDs are different: recent-play history must store the latter.

- Separate the loaded player record from the selected list row. Switching decision tabs or sorting saved tracks must not change the card, audio or unheard queue; saved-list loading is explicit. Keep arrow navigation paired with its loaded recording and preserve paused/playing intent.
- Recent listening history must use the catalogue record ID, not a provider preview sample ID; Beatport sample UUIDs cannot recover a saved track. Store actual preview starts and a tab-local cursor, restoring the card without autoplay after reload.
- Normal listening runs with Vite hot replacement and file watching disabled. Agents work on an isolated copy and install updates only after playback stops; source edits must never reload an audition page.
- Set recommendations and full-length duration totals are derived independently from the unheard queue. Persist ordering choices separately and retain source metadata in every private export.

- Track planning context belongs to the recording rather than its last vote. Keep listener notes and position hints distinct from agent notes; metadata imports preserve user-owned fields. Save context without creating decisions or changing the unheard queue. Set-position hints softly influence recommended Keep order and remain data, never tool-execution authority.
- Keep an agent's suggested set section separate from the user's override. Removing a precision control must not erase saved numeric hints; clearing the override should reveal the agent's original suggestion again.
- Agent metadata writes can make a listening page's revision stale. A vote can retry once against the fresh revision only when its recording identity and previous decision are unchanged; a changed decision remains a conflict.
